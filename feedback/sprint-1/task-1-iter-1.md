### ПЛЮСЫ 👍

Привет, Илья

- PerfectPixel 95%

- Семантика

### БАГИ 🐞

- У контента (body) отсутствует border-radius: 8px
- Контент не центрирован по вертикали
- У поля поиска отсутствуют состояния Hover и Active
- При фокусе у поля поиска появляется обводка (outline)
- При фокусе поля поиска отображается кнопка лупы, но не отображается кнопка очистки
- Текст из поля поиска не выводится в консоль
- При фокусе размер шрифта в поле поиска не по макету, он слишком маленький

### РЕКОМЕНДАЦИИ 💡

- По макету для поля поиска использовать псевдокласс :focus-within (Active)
- У инпута удалена обводка (outline: none), также установить размер шрифта 20px
- У html используется flex для вертикального центрирования контента (align-items: center), высота задаётся через min-height: 100vh
- По макету у фона контента должен быть blur(25px)
- Рекомендуется добавить скрытый `<h1>` внутри `<main>` для сохранения семантики и доступности (a11y). Он визуально скрывается через CSS, но остаётся доступным для скринридеров.
.visually-hidden {
position: absolute;
width: 1px;
height: 1px;
margin: -1px;
padding: 0;
overflow: hidden;
border: 0;
clip: rect(0, 0, 0, 0);
white-space: nowrap;
}
Также рекомендуется добавить в форму скрытый `<label>` с for/id. Он будет связан с полем ввода и останется доступным для скринридеров
- Ссылке с логотипом рекомендуется добавить aria-label — текстовое описание для скринридеров. aria-hidden="true" скрывает SVG-иконку от скринридеров, чтобы она не озвучивалась отдельно, так как описание уже задано через aria-label. Например:
 `<a href="index.html" aria-label="Перейти на главную страницу">`
`<svg class="logo" width="192" height="48" aria-hidden="true">`
…
`</svg>`
`</a>`
Также aria-label добавляется прямо в `<button>` и заменяет текстовое описание, так как внутри находится только иконка
- `<section class="carousel">` расположен вне `<main>`, рекомендуется поместить его внутрь для корректной семантики
- Логику смены кнопок можно реализовать на CSS с использованием псевдокласса :placeholder-shown

В целом отличная работа, особенно в работе со стилями html и body. Будет здорово, если исправишь замечания. Оценка - 4

**Не критичные баги**

### РЕКОМЕНДАЦИИ 💡

- Формально по БЭМу ошибок нет, но применяется он не совсем правильно. Например search-input, search-btn явно должны быть элементами блока search.
- `<!-- Лого -->` такого рода код лучше убрать. Комментарии нужны только если надо объяснить что-то непонятное или не очевидное.
- 0px - не пишут. Пишут просто 0.
- В сss переменные можно вынести больше вещей.  #f5f4f4, #707070, border-radius: 8px; gap например.
- letter-spacing: 0px; не надо указывать. Он и так 0 по умолчанию.
- font-variant-numeric: lining-nums;  font-feature-settings: "lnum"; - можно указать для всего body и все.
- font-family: var(--main-font); - вот тут нужно указать запасной шрифт через запятую.
- padding-top: 12px;  padding-right: 16px;  padding-bottom: 12px;  padding-left: 16px; - можно одной строчкой padding: 12px 16px;
- Для тэга input нужно указать label и связать их через id
- Чтобы текст введенный в поиск выводился в консоль необходимо создать в корне файл с расширением .js. Обраться к нужному тебе элементу через document.querySelector() и вывести его значение в консоль console.log(твойЭлемент.value).
- Еще необходимо сделать замену иконки при введенном тексте. Можно сделать это силами css через placeholder-shown
- атрибут `datetime` для элемента ``<time>`` должен содержать машиночитаемую дату (и время) в формате, определённом спецификацией. datetime="2024-01-06T11:29:00"
- Обязательно должен быть заголовок h1. Причем на странице он должен быть только один и отражать всю суть этой страницы. В данной работе будет правильным сделать h1 скрытым и в нем описать главную суть всего приложения. Также внутри `<section>` обязательно должен быть заголовок. Хотя бы один.
- При добавлении кнопки сброса текста не забудь реализовать все состояния указанные в макете, а также не забудь про доступность (aria-label).
