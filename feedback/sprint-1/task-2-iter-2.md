### РЕКОМЕНДАЦИИ 💡

Рекомендации:

1. Название файлов и переменных в соответствии с их назначением (это намного улучшает и ускоряет читаемость кода). А то чтобы понять за что отвечают функции chichi(); или gaga(); - нужно лезть в сами функции и изучать код. А на это уходит время.
2. Использовать современные типы переменных js. Переменная var устарела. Вместо неё используются const - для постоянных переменных (не изменяемых) и let - для изменяемых переменных. Например, вместо:
var cross = document.getElementById("cross"); - использовать :
const cross = document.getElementById("cross");
А вместо var isInputFocused = false; использовать let isInputFocused = false;

## Kolbasa00 (Владислав) – ⭐ 4

### ПЛЮСЫ 👍

- Грамотная структура проекта: стили разбиты по отдельным файлам (компонентный подход), скрипты вынесены в отдельную папку, данные — в папку `data`.
- Метеоданные вынесены в отдельный файл (`scripts/data/cards.js`), как и требовалось в задании. Карточки заполняются из переменной — основное требование выполнено.
- Шрифты подключены в современном формате `woff2` — это оптимальный выбор для веба.
- Используется семантическая вёрстка: ``<header>``, ``<main>``, ``<footer>``, ``<section>``, ``<search>``, теги ``<time>`` с атрибутом `datetime`.
- Визуально скрытые заголовки реализованы через класс `.visually-hidden` — правильный подход для доступности.
- Иконки вынесены в SVG-спрайт (`sprites.svg`) и подключаются через ``<use>`` — хорошая практика.
- Атрибут `lang="ru"` указан корректно.
- Есть забота о доступности: `aria-label` на логотипе, `aria-hidden="true"` на декоративных SVG, ``<label>`` для поля поиска.
- CSS-переменные используются (`var(--main-font)`, `var(--blur25)`, `var(--border-radius8)`) — удобно для поддержки и масштабирования.
- Фоновое изображение в формате `.webp` — современный и оптимизированный формат.

### БАГИ 🐞

1. **Пробел в имени файла изображения.** Файл `broken clouds.png` содержит пробел в названии. Это может вызвать проблемы при загрузке на сервер и в некоторых системах. Используй дефис или нижнее подчёркивание: `broken-clouds.png`.
2. **Универсальный сброс стилей через `*`.** Сброс `margin`, `padding`, `box-sizing` через `*` — допустимый подход, но установка `font-family` на `*` — избыточна. Достаточно задать шрифт на `body`, и он унаследуется.
3. **Класс `body` на теге ``<body>``.** Ты используешь ``<body class="body">``, что выглядит избыточно. Стили можно задать напрямую селектору `body` без дополнительного класса. Если используешь БЭМ, `body` обычно не является блоком — он служит контейнером для блоков.
4. **ID в стилях и именование по БЭМ.** В HTML используются `id="weatherCards"`, `id="cross"`, `id="loupe"`, `id="valueDisplay"`. Если они используются только для JS — допустимо, но убедись, что для стилей применяются исключительно классы по БЭМ. Также `id="search__input"` выглядит как БЭМ-класс в атрибуте `id` — лучше использовать другое именование для id (например, `id="searchInput"`), чтобы не путать с CSS-классами.
5. **Жёстко заданные размеры контейнера.** `width: 1120px`, `height: 472px` — фиксированные значения. Даже при `min-width: 1280px` это ограничивает гибкость. Для высоты лучше использовать `min-height` или убрать фиксацию, чтобы контент определял размер.

### РЕКОМЕНДАЦИИ 💡

1. **Добавь ``<noscript>`` для случая отключённого JS.** Поскольку карточки генерируются через JavaScript, при отключённом JS пользователь увидит пустую страницу. Добавь fallback.
2. **Используй ``<time>`` в карточках рассвета и заката.** Если в генерируемых карточках есть время рассвета (8:42) и заката (16:37), оберни их в ``<time datetime="08:42">`` и ``<time datetime="16:37">`` для семантической корректности — так же, как ты уже сделал в блоке `.weather`.
3. **Добавь ``<meta name="description">`` в ``<head>``.** Это важно для SEO и описания страницы в поисковой выдаче:HTML

`<meta name="description" content="Прогноз погоды — актуальные метеоданные по городам">`
4. **Порядок CSS-правил.** Хорошей практикой считается группировка CSS-свойств в определённом порядке: позиционирование → блочная модель → типографика → визуальные эффекты. Это облегчает чтение и поддержку кода.
